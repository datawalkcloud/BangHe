## 修复「从价目表自动带入价格」流程的缺口

- 排查范围：发布新价目 → `price_list` → 工作台 `SettlePanel` 取价/带出 → 结算落库。
- 发现的缺口（Case C）：当该品种+等级+业务日期**无生效价目**（`listed == null`）而人工填价时，前端 `deviates` 恒为 false →
  - 结算 payload 变成 `price_list_id=null` 且 `price_override_reason=null`；
  - 改价事由输入框不渲染、`blocked` 不拦、结算按钮可点；
  - 但 Rust 后端 `orders.rs:1725` **会拒绝**（`price_list_id` 为空且事由为空 → Err「手填单价必须填写改价事由」），`orders_contract.rs:480-484` 有对应断言。结果：用户在「无价目」场景被后端挡死却没有任何输入事由的路径。
  - 另外 mock `api.settle` 未做该校验，与真实后端口径不一致，掩盖了问题。
- 修复：
  - `SettlePanel.tsx`：新增单一判据 `matchesList`（现行价目原价取值）与 `needsReason = 有价 && !matchesList`；`price_list_id` 用 `matchesList` 决定，`price_override_reason` 用 `needsReason` 决定；事由输入框改由 `needsReason` 渲染；`blocked` 按「偏离 / 无生效价目」分别给文案；`PriceField` hint 增补「无生效价目，手工定价」。
  - `src/mock/api.ts` `settle`：补同样的闸门（手填价无事由抛错），与 Rust 端同口径。
  - `OrderDetailPage.tsx`：事由 CallOut 标题按 `price_list_id` 区分「单价偏离价目表」/「手工定价（当时无生效价目）」。
- 验证：`tsc --noEmit` 通过（exit 0）。语义口径以 Rust 端为准：**无 `price_list_id` ⇒ 必须有改价事由**。

## 修「打印效果和预览不一样」（现场热敏票跑到两张纸上）

现场反馈：热敏小票上**每个字段的标签和数值都被拆成两行**，数值孤零零另起一行还带一长串空白；金额印成 `&#165;122,133.40` 这样的字面量。逐层排查后定案**三个真 bug**，全在 `ticket-core`：

1. **`¥` → `&#165;`（字库缺字退化成 HTML 实体）**
   - 根因：`new_printer` 用 `Encoder::new(GBK).allow_unencodable(true)`；`escpos` 0.20 的 `Encoder` 文档明写"unmappable characters will be replaced with **HTML numeric character references**"（`encoding_rs` 的 WHATWG 行为）。半角 `¥` U+00A5 **不在 GBK 里**，于是被编成 6 个 ASCII 字符 `&#165;` 原样印在票上。测试断言 `GBK.encode("¥").2 == true` 已坐实。
   - 修法：`render.rs` 新增 `gbk_safe()`（`¥` → 全角 `￥`，GBK 的 A1E3；其余不可映射字降级为 `?`），所有文本走唯一出口 `put(p, s)`。**宽度必须在净化之后算**——全角 `￥` 占两列，折点会变。`write_weigh_ticket` / `write_self_test` 的裸 `p.write` 也一并收编。
   - 另加 `glyphs_used_on_tickets_are_in_gbk`：把票面实际用到的符号（全角下划线 `＿`、破折号 `—`、间隔号 `·`、全角括号、`￥`）列成清单守着，缺了会被静默换成 `?` 只有打出来才发现。

2. **kv 溢出被打印机硬折（本次"跑到两张纸上"的主因）**
   - 根因：`kv()` 用空格填充到恰好 `cols` 列。实机列数比声明的 48 小（照片里纸宽像 58mm），整行超宽 → 热敏机在边界上自己折 → "标签一行 / 数值另起一行带空白"的破相。
   - 修法：`kv()` 加 `need + 1 > cols` 判断，放不下就退化成**有意的两行式**（标签一行 + 数值整行右对齐，新增 `right()`），不再交给打印机硬折。`pair()` 同理退化成两行 kv。
   - 关键副作用：这个修法只在 `cols` 正确时生效——`cols` 偏大时判断根本不触发。所以必须让 `cols` 可实测，见第 3 点。

3. **倍宽行撑破纸宽（守卫测试新抓出来的）**
   - `write_lines` 的 Text 行原样用 `wide`（站名 `wide:2`），在 24 列的机器上物理占 28 列 → 站名自己折成两行。
   - 修法：先按 `cols / display_width(text)` 把字号压到"整行放得下"，折行预算再按压缩后的倍数折算 `wrap(&text, cols / scale)`，于是任何配置下每段都必然塞得进纸宽。

**让列数可实测（新增能力）**
- `Paper::cols_with(Option<u8>)`（`model.rs`）：实测值覆盖标称，<16 列按误填退回标称。
- `write_lines` 签名由 `paper: Paper` 改为 `cols: usize`；`ReceiptPrintInput.cols`（Rust）→ `nativePrinter.receipt({ cols })` → `useReceiptStore.thermalCols`（**站点级**，null = 按纸型；列数是机器属性，不该让站长给六种票据各填一遍）。
- `write_self_test` 末尾新增 `ruler(p, cols)`：每 5 列 `+`、每 10 列打十位数字，**折在第几格就是实机列数**，配套文字说明印在同一张纸上。
- `TemplateEditor` 基础设置新增「小票机列数」下拉（自动/48/42/32/24），与「小票机自检」配对使用；`ReceiptPrintPreview` 与编辑器的打印测试都会带上这个值。

## 诊断：设备中心摄像头「没有画面」（只出诊断，未改代码）

用户反馈「本机摄像头正常，但设备中心里显示不出来」。排查后定性：**不是驱动/权限问题，是画面通道从来没实现过**。三处断点：

- **扫描可用，但只在桌面端**：`camera_list_local`（`src-tauri/src/camera.rs`，Media Foundation 枚举 VIDCAP）是真的；`DevicesPage.tsx::runCameraScan` 在 `!runningInTauri()` 时直接短路回「浏览器预览扫描不到本机摄像头」。用 `npm run dev` 看必然没有列表。
- **全前端零画面渲染**：`src/components/workstation/CameraPanel.tsx` 与 `DevicesPage.tsx:1644` 的 `CameraPanel` 都是纯文字占位（"实时抓图"/"尚无抓图记录"），全工程无 `<img>`/`<video>`、无拉流代码。工作台的定时器只刷新右下角时标。
- **本机 UVC 连抓拍都没接**：`camera.rs` 只服务内网 IP 摄像机 HTTP 抓图；`capture_snapshot` 里 `transport == "local"` 的分支（约第 918–931 行）明确按「无抓拍」降级。
- **附带**：`devices.rs::probe_plan`（第 610–631 行）只给 escpos 小票机 / 精伦读卡器接了真通道，**摄像机点「联机测试」必回 `该驱动（xxx）暂未接入本机探测通道`**（`ProbePlan::NotWired`）。摄像头登记走 `createDevice`/`updateDevice`，不经 `update_device_config` 的 verify 门禁，所以**配置能存上**，只是存上之后没画面。
- 文档承诺未落地：`02-功能模块规划.md:321`（摄像头配置 P0「支持测试抓图并预览」）、`04-硬件对接方案.md:416`（一键测试「摄像头：显示抓拍缩略图」）。

**三条候选路线（未实施）**：
- A. WebView2 `getUserMedia` 前端直出——只覆盖本机 UVC。**已核实：项目锁的 tauri 2.11.5 没有 `on_permission_request`**（docs.rs 2.11.5 的 `WebviewWindowBuilder` 无此方法），要走这条路得升 tauri，或用 `webview2-com`（lock 里已有 0.38.2，配 wry 0.55.1）走 `with_webview` + `ICoreWebView2Profile4::SetPermissionState` 自己处理权限。WebView2 默认会弹一次权限框，但**拒绝一次即持久化拒绝**（存于 `EBWebView/Default/Preferences`），现场误点就再也弹不出来。另：浏览器 `MediaDeviceInfo.deviceId` 是加盐哈希，**与 Media Foundation 的符号链接不是一回事**，只能用 label 匹配台账里的 `deviceName`，且 label 要先授权才有值。
- B. Rust `nokhwa` 抓帧推前端——唯一能统一本机 + 网络摄像机的路；代价是新依赖 + 设备独占。
- C. 复用 `camera.rs::target_from_config` + `grab()` + `check_jpeg()` 开一个预览命令——**零新依赖**，`base64_standard` 已在文件里现成；但只对内网 IP 摄像机有效。注意预览应**不落 attachment 表**（模块头注：无归属的"野图"比丢图更糟），且 `grab()` 是阻塞的（最长 3s 连接 + 3s 读），命令必须 `spawn_blocking`（`camera_list_local` 已是这个写法）。CSP 为 `null`，`data:`/`blob:` 图片不受限。
