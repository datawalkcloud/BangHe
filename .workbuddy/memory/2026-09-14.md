## 修：工作台自定义布局"点完成后切走再切回来又回退"（`components/workstation/layout.ts`）

**根因**：`useWorkstationLayout` 的保存链路只写了库（`api.setPref`），**没有回填 react-query 缓存**。
`useQuery({ staleTime: Infinity })` 下，工作台是路由组件、切页即卸载，重挂载时 `loadedFor` ref 清零、
缓存又不会重取 → 保存前那份旧文本被当成本人排布 `parseDoc` 灌回本地状态。

**改法**（`layout.ts`）：
- `mutationFn` 先算出 `json = stringifyDoc(settle(next))` 并领一个写入序号 `++writeSeq.current`，
  resolve 出 `{ json, seq }`；
- 新增 `remember(json, seq)`：序号是最新那次才 `queryClient.setQueryData(["pref", LAYOUT_KEY, actorId], json)`
  **并**把 `loadedFor.current` 标成同一戳（本地已经是它了，别被回灌一次——拖动中防抖落库时回灌会把
  正拽着的块弹回挤干净后的位置）；
- `onSuccess` 走 `remember`；`onError` 也走（用当前序号）：提示语说"本机仍生效"就得真生效，
  否则切页回来调整没了，比"重启后回到原样"更难受。

**同源对照**：`useCloseBehavior` / `useSoftKeyboardSetting` 本来就有 `setQueryData`（它们的显示值直接派生自
`query.data`，不回填会显示旧值）。`useSidebarWidth` 缺这一步，但侧栏在 AppShell 里常驻不卸载，暂时看不出问题——
若哪天侧栏会随路由重挂载，同一个坑会复现。

**顺手清掉**（非本次引入）：`QcPanel.tsx` 一处未收尾的重构残留——`needMoisture` / `moistureMiss` 已删，
但 `hint={cmp.text}` 撞上联合类型（占位支 text 为 null）。改成 `cmp.text ?? undefined`。

**验证**：`npx tsc --noEmit --incremental false -p tsconfig.json` → exit=0 零输出；
`npx vite build --outDir dist-verify --emptyOutDir` → 4.98s 干净（仅预存的 Tauri 动态导入 warning）。

## 改：结算凭证出厂默认印一维条码（`print/receipt/defaults.ts`）

**需求**：用户一句"计算凭证 小票模板，默认打印条码"。追问后确认口径：**仅一维条码（CODE128）**，
且**只改结算凭证**，过磅单那枚凭票码保持二维码不动。

**改法**：`defaultTemplate("settlement_voucher")` 的码区块加 `codeStyle: "barcode"`
（原为缺省的 `"qr"`），区块位置/标题/`qrCaption` 都不动。纸型仍是 A4：
`measureCode128` 在 A4 上不触发压缩（`dots = CODE_SCALE_DOTS[2] = 4`，条高固定 96 点 = 12mm）。

**为什么这两张票的默认码制不一样**（写进注释了，免得后人当成不一致来"统一"）：
结算凭证的归宿是结算窗口那支几十块的键盘口激光枪（解不动二维码），过磅单那枚是影像枪/手机扫的。
`codeStyle` 的**字段缺省值仍恒为 `"qr"`**——老模板没这个字段，缺什么照历史行为来；
`defaults.ts` 只决定"出厂默认模板长什么样"，两者不是一回事。

**老用户不受影响**：覆盖模板照旧以用户存的为准（`store.ts` 取用规则），
`ensureRequiredBlocks` 只兜底 `required` 区块、本块不是 `required`，故不会强插。

**验证**：`scripts/receipt-code/check.ts` 新增 F1–F4
（凭证仅条码 + 发到机器的行序列里无 qr 有线码 + A4 不压缩 + 过磅单仍是二维码），

## 改：称重区手录与刷卡同权（含"手录后不出票"的根因）

**需求**："称重区手工录入读数要实现和刷 ic 同等效果，包括自动打印等逻辑。"

**先核过再问**：把 `WeighPanel.submit(..., "manual")` 与 `useIcWorkflow.advance` 两条路从头读到
尾，确认手录**早就**接在同一个出口上（`onNetDetermined` → 出码单 + 自动挂账/弹框），服务端
`orders.rs::capture` 对 `source="manual"` 也没有额外闸门。于是拿三个具体缺口去问用户，用户勾了
三项：**离线时按钮直接手录**、**手录后确实没出票**、**无卡站点缺结算入口**。第三项是新增，第一项是
入口问题，第二项是真现象——说明"同一个出口"这个结论还不够，得找出两条路**机制上的差异**。

**根因（不出票）**：`useIcWorkflow.advance` 判"净重刚定"用的是**捕获前自己 `api.getOrder` 取的那份
快照**；`WeighPanel.onSuccess` 用的却是 **`order` 这个 prop**。prop 来自 `["order", 单号]` 这条查询，
后台重取 / 窗口聚焦重取 / 上一捕失效引发的重取，任何一个都能在"发出捕获请求 → 回执到达"这段窗口里
把它换成**已含净重**的新值，判据于是静默变成 false：票不出、结算不走，连个错都不报。修法是照刷卡
那条路统一口径——`mutationFn` 里取一份快照（与 `grabCaptureFrames` 并发，不多等一个来回），落到
`priorNet` ref 给 `onSuccess` 用。

**顺带堵掉同类的第二个静默失败**：`triggerPrint` 原来是把 `directPrint` 这个 boolean 置 true，
直打 effect 读完再置回 false。`setState(同值)` 不引发重渲染——**目标单号没变、布尔量又已经在位**
（连续两车之间不导航、同一张单再打）时，整次 `triggerPrint` 退化成空操作，effect 不重跑，票静默不出。

## 核：票面无价，以及「自动挂账」那一支是逻辑死循环（用户质疑"这流程合理吗"）

**用户问**："现在的流程只有结算的时候才有价格，磅单打印的时候没有价格，这流程合理吗"。只查不改，等定方向。

**核出来的四件事**：

1. **票面无价本身是设计写的，不是漏做**：`docs/design/02` F1.4「先过磅、先打码单把票给客户，钱当时
   不算」「磅房只管出票，价在结算窗口定」；凭票码只装定位符的理由在 `scenarios.tsx:526`（票先打、
   价后算，金额进码＝让客户自己改价）。这条站得住。
2. **"自动挂账"那一支是逻辑死循环，不是「很少触发」**：`weigh_order.price_fen_per_ton` 全项目只有
   `orders.rs:2279` 一个写入点（无 `order_set_price`；`order_update` 只碰车牌/备注；制单与 mock 置
   null），而那条 UPDATE **同一条 SQL 里就带 `status='settled'`**（`orders.rs:2283`）→
   `postWeighAction` 首判 settled 即 `return { kind: "none" }`。有价 ⇒ 已结算 ⇒ 第一分支就返回，
   **这一支永远到不了**。上一轮日志写的"现实中基本不会触发"是低估，实际是逻辑上不可能。
3. **结算前打的码单票面印一排「—」**：默认模板 `defaults.ts:47-48` 印 `price_per_kg / goods_amount /
   payable_amount / paid_amount / payable_upper / payment_status_label / payment_method_label`，
   `resolveField` 读的正是这些列，`format.ts:14` 的 EMPTY 就是 `"—"`。
4. **02 §F1.4 写的"码单上可印预估应付…必须标明是预估"未实现**：全项目搜 `预估` 只有
   `ScanSettlePage.tsx:412` 一个 label；`WEIGH_FIELDS` 里没有 `est_*`，`resolveField` 的 ctx
   （station/names/order/qc）里也拿不到价目表。

**另一个时序后果**：`handleNetDetermined` 是先 `triggerPrint` 再结算，所以磅房那条路走完之后，
客户手里**一张带价的纸都没有**——自动支不补凭证、弹框支票已经在定价之前打掉了。

**判断**（已当面给用户）：票面无价对"磅房出票、客户去窗口/周末结"的粮站是对的；但上一轮把结算搬进
磅房那一刻，"票先打、价后算"的前提就没了。三条方向让用户选：补预估应付（补齐 02 §F1.4）／
结完补打一张带确定价的码单／加结算前填价入口并改掉自动挂账的判据（会推翻上轮"只认磅单已落库单价"）。

## 修：手动录入皮重后出票，票面皮重是空的（`pages/WorkstationPage.tsx`）

**现象**：手录皮重 → 净重凑齐 → 票出来了，但票面「皮重」那一格没有数。

**先排除掉的两层**（都跑过实证，不是读代码猜的）：

1. **落库没问题**：只读挂载开发库（`%APPDATA%\cn.datawalk.bh\banghe.db`）直接看列——
   `BD01202609000004 / 003 / 001` 三张已结算的单 `tare = 2000`（200.0 kg）、`net = 10000`，
   `weigh_record` 也在。`orders.rs::capture` 的 UPDATE 本来就带 `tare_weight_01kg`。
2. **票面渲染没问题**：把 `receiptLines`（`print/receipt/escpos.ts`）单独用 esbuild 打包后在 node 里
   跑，喂 `tare_weight_01kg: 2000` 出的是「皮重 | 200.0 kg」；喂 `0` 才出「0.0 kg」，喂 `null` 出「—」。
   过磅单场景只有**一份** `resolveField`（`scenarios.tsx:494`，热敏与 A4 共用），
   `case "tare_weight"` 读的就是 `o.tare_weight_01kg`，全项目没有第二处取皮重（`sheets.tsx:150` 那处
   是 A4 整页版式，同一个 `Line`）。

**根因：出票读的是写库之前那一份 react-query 缓存。** `WeighPanel.capture.onSuccess` 里的顺序是

```
if (priorNet.current == null && o.net_weight_01kg != null && …) onNetDetermined?.(o);  // ← 这里出票
qc.invalidateQueries({ queryKey: ["order", o.order_no] });                            // ← 失效在后面
```

而 `triggerPrint` 只是 `setPrintTarget` + `printSeq++`，真正的 `printReceipt` 在 effect 里读
`["order", printTarget]` 那份**还没被失效、也还没重取**的缓存——手录皮重那一刻它是"捕皮重之前"
的快照（`tare = null`），于是票面印出空格。**它只在 `handleNetDetermined` 的 `dialog` 支与
`autoSettle.onError` 支上暴露**：自动挂账成功那一支上一轮（改定价时）已经补过一句
`refetchQueries(order)`，所以那两条路印出来是对的——这也是"同一个出口，时好时坏"的来源。

**改法**（一处收口，四条出票路径共用）：`triggerPrint` 从同步改成 `async`，**先把这一单拉成最新的再推进出票**：

```ts
const target = no ?? order?.order_no;
if (!target) return;
try { await qcClient.refetchQueries({ queryKey: ["order", target], type: "all" }); } catch { /* 取不到就照缓存印 */ }
const fresh = qcClient.getQueryData<WeighOrder | null>(["order", target]);
if (fresh && fresh.net_weight_01kg == null) { toast.warning(…净重未定…); announce(…); return; }  // 与 TicketPrintSection::canPrint 同一道闸
printedFor.current = null; setPrintTarget(target); setPrintSeq((n) => n + 1);
```

- **`type: "all"` 不能省**：默认档位只重取 active 的查询，补打一张当前没显示的单（磅单详情直打、
  结算框给别的单出票）时那份缓存是 inactive，默认档位放着旧数据不动 —— 又回到印旧快照那条老路。
- `refetchQueries` 在 v5 返回 `Promise<void>`，所以取新值只能走 `getQueryData`（不能拿返回值）。
- 四个调用点全部改成 `void triggerPrint(...)`（返回值现在是 Promise）；`autoSettle.onSuccess`
  里上一轮那句"出票前先 `refetchQueries`"删掉——现在是 `triggerPrint` 自己的职责，两处都留会等两遍。
- 顺带补上"净重未定不出票"：以前 F9 能把一张只有毛重的单印出来，票上连重量都没有。

## 修：80 机装 58 卷，条码被切在纸外（热敏居中用错了轴）

**现象**（用户原话）："当使用80打印机打印58尺寸时，条码超出了纸张，他实际还是80宽度居中打印的。"

**根因**：热敏那一路的二维码/一维码一直靠 `ESC a 1`（`justify(CENTER)`）居中，而**固件居中的基准是
打印头的可打宽度，不是这卷纸的宽度**——那个数只跟机身有关。80 机（576 点 / 72mm）装 58 卷（464 点 /
58mm）时，48mm 宽的码落在 12~60mm，纸只有 58mm，右端连着 CODE128 的停止符一起被切掉：票看着出全了，
扫码枪读不出来。

**正文早就绕开了这个坑**（`render.rs::aligned` 用前导空格补齐，不交给 `ESC a`），码是最后两个漏网的。

**改法**：落点从"交给固件"改成"前端算好、机器照点排"。

| 位置 | 改动 |
| --- | --- |
| `code-size.ts` | 新增 `headDots()`（58 机 384 / 80 机 576）、`rollDots()`（58 卷 464 / 80 卷 640，定长纸 0）、`codeBudgetDots(paper, machinePaper?)`（取纸的可打宽与机头宽里更窄的）、`codeOffsetDots(codeDots, paper, machinePaper?)`（轴 = min(纸卷幅宽, 机头宽)，落点 =(轴−码宽)/2，定长纸恒 0）；`fitModuleDots` 签名由 `(modules, paper, want)` 改成 **`(modules, maxDots, want)`**——压缩要按"预算"压，不是按纸宽压 |
| `code128.ts` | `measureCode128(data, paper, scale, maxDots?)` 多一个可选预算参数，缺省仍是 `printableDots(paper)` |
| `QrGraphic.tsx` | 新增 `qrSideDots(text, scale)`：二维码边长也报点（原来只有 `qrSideMm`，毫米反推会丢精度） |
| `native.ts` | `NativePrintLine` 的 `qr` / `barcode` 两支各加可选 `padLeft?: number`，注释写明"固件居中的基准是机头宽，所以落点由前端给" |
| `escpos.ts` | `receiptLines(template, ctx, opts?: { machinePaper? })`；`qr` 支发 `padLeft: pad(qrSideDots(...))`，`barcode` 支发 `padLeft: pad(geo.modules * geo.dots)`；`pad = (d) => codeOffsetDots(d, template.paper, machine)`、`maxDots = codeBudgetDots(...)` |
| `silent.ts` / `ReceiptPrintPreview.tsx` / `TemplateEditor.tsx` | 三个调用点把"这次出纸告诉机器的纸"传进去（热敏 → `target.paper`；预览/测试打 → 框里选的那张）。**这是 `machinePaper` 的来处**：票面按 80 排、机器装 58，这两个值本就不同 |

| `src-tauri/src/queue_print.rs` | `PrintLine::Qr { text, size, .. }` / `::Barcode { runs, dots, height, .. }`：**刻意忽略** `pad_left`——GDI 那边由驱动自己的可打区居中，前端别越权。已加注释说明这处分歧是有意的 |

**为什么装态一致的站点（80 装 80、58 装 58）分毫不差**：轴取 min 之后，80 纸对 576 点头时

## 修：空值打成横杠，横杠被换行单独打一行（热敏列宽算错一列）

**现象**（用户原话）："当皮重净重为空时打印了横杠，但是打印出来的小票把横杠换行单独打印的"

**根因**：`render.rs::char_width` 用一张**手写 Unicode 区段表**判全角，而 `—`(U+2014) 落在
General Punctuation 段——**不在表里任何 CJK 区段**，被算成 1 列；可它在 GBK 里是双字节（A1AA），
打印机一律按全角画（2 列）。于是 `kv` 少算一列：

```
"皮重"(4) + 26 空格 + "—"(实为 2)  →  纸上 33 列，纸只有 32 列
```

行尾正好顶到纸宽 → 热敏机在边界上**自己硬折**（溢出不会截断，只会折行）→ 横杠被甩到下一行单独打。
**有数值时全是 ASCII 算得对，所以只有空值才犯**——极易误判成"空值分支有问题"。
同类受影响的还有 `…`(U+2026)、`“”`、`·`（车牌间隔号）等全角标点。

**改法**：判据不再手写码表，改成**直接问 GBK——编出来双字节即 2 列，其余 1 列**
（`GBK.encode(c.encode_utf8(&mut buf))`，与 `gbk_safe` 同一口径：编不出的出门前已是 `?`、半角 `¥`
已是全角 `￥`，折点才不会和纸上错位）。

**踩到的一个测试陷阱（值得记）**：新写的回归第一版断言用 `display_width` 当基准——**那就是被测函数
自己**，它算错了会连断言一起错，测试自洽通过、坑还在。改成独立口径 `physical_cols()`（数 GBK 字节：
`<0x80` 记 1 列，否则 2 列）之后才抓得住。`emitted_bytes_never_overflow_the_grid`、
`alignment_follows_the_layout_columns_not_the_head_width` 那几处宽度断言也一并换成它。

**验证**（`crates/ticket-core`）：
- 新增 `gbk_full_width_punctuation_is_two_columns`（`— … “ ” ·` 各 2 列 + ASCII 不受影响）
  与 `an_empty_value_stays_at_the_end_of_its_row`（P58/P80 两档纸各跑 `皮重/净重 = —`，
  钉住"只有两行" + "行宽**正好**等于纸的列数" + "横杠留在行尾"）。
- **用临时回退验证过守卫是真的**：把 `0x2010..=0x2027` 改回 1 列 → 两条用例都红，
  `an_empty_value_stays_at_the_end_of_its_row` 报 `left: 33, right: 32`（正是那一列）。已还原。
- `cargo test` → **16 全过 / exit=0**；`cargo check`（`src-tauri` / `tools/escpos-probe`）各 exit=0。

**另一条通用结论**：**预览永远看不出这类问题**——`render.tsx` 用 flex 画 SVG，根本不做列宽算术。
凡是"预览对、纸上歪"，先怀疑 Rust 侧的列宽/折行，别在前端找。已写进 `topics/print.md` 新的一节
「列宽：判据不手写码表，直接问 GBK」。

## 修：58 纸上条码只占半张纸（压缩只取整数点，中间没有档位）

| 改前 | 1 点（0.125mm） | 233 点 = **29.1mm** | 50% |
| 中间档 | 2 点 | 466 点 = 58mm | 出纸（正是上一轮"条码超出纸张"） |
| 改后 | **1.52 点**（0.19mm） | 354 点 = **44.2mm** | 76%，整条铺满 48mm 可打宽 |

**根因**：`fitModuleDots` 用 `while (dots > 1 && …) dots -= 1` 只取整数点。模块数一旦超过纸宽
点数的一半，1 点和 2 点之间就没有值——于是"压小"和"铺满纸宽"被这个写法弄成了互斥的两件事，
纸白白缴掉一半，而且 0.125mm 的模块细到枪读不动。

**改法**：压小改成按**实数**压（`min(want, maxDots / modules)`，下限 1 点）。
由此带出契约改动——`GS v 0` 栅格只认整数点，小数那一份必须在某一处折掉：

| 位置 | 改动 |
| --- | --- |
| `code-size.ts` | `fitModuleDots` 返回实数；新增 `MIN_MODULE_DOTS = 1`（栅格画不出半点） |
| `code128.ts` | `BarcodeGeometry` 新增 `widthDots`（条身整数点宽），与实数 `dots` **同在 `measureCode128` 一处产出**；`shrunk` 改判 `dots < want` |
| `native.ts` / `model.rs` | `Barcode` 的 `dots` → **`width`**（整条点宽） |
| `escpos.ts` | 发 `width: geo.widthDots`；落点改按 `widthDots` 算（静区不进栅格，纸边白纸就是静区） |
| `render.rs::barcode` | 按累计模块数 `round(cum*width/total)` 分摊到每段——整条宽度分毫不差、每段至少 1 点 |
| `queue_print.rs` | 按 `width / 总模块数` 摊回每模块几点（A4 从来不是窄的那一方，整除即可） |
| `TemplateEditor.tsx` | 提示里的 `点/模块` 改 `toFixed(2)` |

**为什么落点改按条身算**：从前是 `codeOffsetDots(modules * dots)` 把静区也算进去，
但栅格里根本没有静区（`body = Σruns × dots`）——预览带着静区、纸上不带，本来就对不齐。

**验证**：
- `scripts/receipt-code/check.ts` → **全部通过**（新增 C10「压过之后仍铺满 ≥98% 可打宽度」、
  C11「整条仍在卷内」、E5/E6「发的是整条点宽 + 落点按条身算」；F3/H10/H11 跟着新字段改）；
- `npx tsc --noEmit --incremental false` → exit=0；`npx vite build` → 5.60s 干净；
- `cargo test`（ticket-core）→ **17 全过**（新增 `barcode_shares_an_awkward_width_across_the_runs`：
  11 点宽摊到 6 模块 → 段宽 4/2/3/2，钉住字节 `F3 80`）；
  `cargo check`（`src-tauri` / `tools/escpos-probe`）各 exit=0。

**顺带的影响（已想清楚，不算回归）**：A4 上选「大 / 特大 / 超大」时从前一律压到 5 点/模块
（158mm），现在压到 5.75（182mm，铺满可打宽度）——"压小"只在真放不下时发生，且压到刚好。

## 改：日期组件全部换成 shadcn Calendar + Popover

**需求**（用户原话）："所有的日期组件没有使用shadcn 的，全部改，并且后续禁止再出现不shadcn 组件的情况"。

**原状**：`ui/date-picker.tsx` / `ui/date-range-picker.tsx` 是**手搓的**——base-ui `Popover.Trigger`
套 `buttonVariants`，里面用 `dayjs` 自己算 6×7 网格、拿裸 `<button>` 画日期。另
`outbound/OutboundFormDialog.tsx:184` 直接用 `<Input type="date">`。全项目 native date input 就这一处。

**改法**：`npx shadcn add calendar popover` 拉官方件（style=base-maia，装了 `react-day-picker@10`
+ `date-fns@4`），两个组件重写成 **shadcn `Popover` + `Calendar`**，对外签名一点没变（仍是
`YYYY-MM-DD` 字符串），所以 `DashboardPage / OutboundPage / MastersPage / OrdersPage /
PaymentsPage / ReportsPage / StockPage / SystemPage` 八个调用点**一行未动**。

三个必须写进注释的坑：
- **`Date`↔字符串只用 dayjs（本地时区）**，不许 `toISOString()`——东八区会把当天算成前一天。
- **`mode="range"` 必须带 `min={1}`**：不给 min 时 `addToRange` 对空区间直接补 `to=同一天`
  （`{from: d, to: d}`），第一次点击就收敛成单日区间并关面板，选不了区间。
- **半程选择只留在内部 `draft`**，凑齐两端才 `onChange`（否则没选完就触发筛选刷新）；
  `min=1` 下"再点一次起始日" RDP 返回 `undefined`，在 `onSelect` 里按**单日区间**收掉，
  不然想选同一天要点三次。
- `weekStartsOn={0}`：`zhCN` 默认周一起，仓库日历口径一直是周日打头（`日一二三四五六`）。
- 保留了 `tnum` / `min-w-0` / `--input-placeholder` 那几条原先为表单网格写的样式，以及
  `presets` / `allowClear` / `invalid` 三个 prop。

**坑（CLI 的）**：`npx shadcn add` 顺手**覆盖了 `ui/button.tsx`**，删掉
`nativeButton={props.render ? false : true}`（用 `render` 换 `<a>`/`<Link>` 时的兜底）。
已按 `git show HEAD:` 取回原文贴回。**以后每次跑 `shadcn add` 都要 `git diff` 看一眼 button.tsx。**

**验证**：`npx tsc --noEmit --incremental false -p tsconfig.json` → exit=0 零输出；
`npx vite build --outDir dist-verify --emptyOutDir` → 5.80s、3765 modules、干净（仅预存 Tauri
动态导入 warning 与 chunk >500kB 提示）。全项目已无 `type="date"`，也无残留的手画日历网格。

`MEMORY.md` 第 5 条。
