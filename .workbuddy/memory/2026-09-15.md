## 修：新建出库单「领出方」下拉空表

- 根因：出库单表单调 `api.listParties("", "all")`，第二参数 "all" 经 `party_list` 命令落到
  Rust `orders.rs::list_parties`，被当成具体类型去比对 `party_type = 'all'`，库里没这类型 → 空表。
  浏览器预览走 mock（mock 里 "all"＝不限）所以不暴露，只有真库（Tauri）才空。
- 改了三处：
  1. `src/components/outbound/OutboundFormDialog.tsx`：改成 `api.listParties("")`（不传＝不限，
     与 `PartiesPage` `type === "all" ? undefined : type` 同一口径）；下拉空态补文案
     「档案加载中… / 暂无可用档案（先到往来单位建档）」，不再静默空表。
  2. `src-tauri/src/orders.rs::list_parties`：`ptype.filter(|t| !t.is_empty() && *t != "all")`
     ——兜底值不再进 SQL，与 `outbound.rs` 状态筛选口径一致。
  3. `src-tauri/tests/orders_contract.rs` 加 `list_parties_treats_all_as_no_type_filter`。
- 验证：`npx tsc --noEmit --incremental false -p tsconfig.json` 通过；
  `cargo test --test orders_contract list_parties` 2 passed。

**通则（下次别再踩）**：界面筛选的兜底值 `"all"` 只在前端层有意义，跨过 invoke 到 Rust 之前
必须转成 `undefined`/`None`；Rust 侧凡是 `Option<&str>` 的枚举筛选，收到 `"all"`/`""` 一律当不限。

## 修：热敏条码左对齐（80 机装 58 卷）——落点的轴取错了

继 09-14 两轮（条码出纸 → 条码只有纸一半）之后的第三次。这次是**修上一轮时修歪的**：
`code-size.ts::codeOffsetDots` 的轴取成了 `min(卷幅, 机头)`。80 机装 58 卷时轴成了卷幅 464，
落点只有 57 点；而卷在机头下是**居中**卡着的，左沿在**头坐标 56**，于是左留白 1 点、右留白 112 点
——条码紧贴纸的左边缘，右边空 14mm。探针实测：

| 票面/机器 | 改前 落点·左留白·右留白 | 改后 |
|---|---|---|
| 58 / 80 | 57 · **1** · **112** ★ | 113 · 57 · 56 ✓ |
| 58 / 58、80 / 80、80 / 58 | 已居中 | 一个数没动 |

- 改成**轴 = 机头点宽**（`offset = (head - codeDots) / 2`）。依据：卷在机头下居中（纸仓壁/定心隔套），
  所以**卷心 = 头心**，"纸上居中"="机头上居中"；且它与正文同轴——`render.rs::aligned` 往 `cols` 列
  补空格，`cols × 12 点`正是头宽，码下方那行说明文字也走 `aligned`。
- 新导出 `rollLeftDots(paper, machinePaper)` = `(head - roll) / 2`，供自检把落点从**头坐标**换算到
  **纸坐标**。旧断言直接拿点数比卷幅，两种坐标混着比，正是漏掉这条的原因。
- 自检 H 段改写：H3/H4 改成"轴是头宽 + 纸坐标下左右留白相等"；H5 回归锚钉住改前的错法
  （落点 57 → 左 1 右 112）；新增 **H13**（四种装态"码中线 = 机头中线 = 卷中线"，不依赖卷宽建模）。
  写 H5 时自己又踩了同一个坐标坑（右留白少减卷左沿），被断言抓出来。
- 只改了 `code-size.ts` + `scripts/receipt-code/check.ts`；Rust 侧零改动（`padLeft` 语义未变）。
- 验证：自检 A–H13 全过；`tsc` exit=0；`vite build` 2.75s；`cargo test`（ticket-core）17 全过；
  `cargo check`（src-tauri / escpos-probe）各 exit=0。

**通则**：凡是"落点/偏移"这类量，**先说清它是哪个坐标系的数**，再写断言。头坐标与纸坐标差
`(头宽-卷幅)/2`，在装态一致时恰好为 0——所以只在"票面纸型 ≠ 机器纸型"时才暴露，
自测的机器本来就一致，永远测不出来。
