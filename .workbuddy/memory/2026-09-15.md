# 2026-09-15

## 修：新建出库单「领出方」下拉空表

- 根因：出库单表单调 `api.listParties("", "all")`，第二参数 "all" 经 `party_list` 命令落到
  Rust `orders.rs::list_parties`，被当成具体类型去比对 `party_type = 'all'`，库里没这类型 → 空表。
  浏览器预览走 mock（mock 里 "all"＝不限）所以不暴露，只有真库（Tauri）才空。
- 改了三处：
  1. `src/components/outbound/OutboundFormDialog.tsx`：改成 `api.listParties("")`（不传＝不限，
     与 `PartiesPage` `type === "all" ? undefined : type` 同一口径）；下拉空态补文案
     「档案加载中… / 暂无可用档案（先到往来单位建档）」，不再静默空表。
  2. `src-tauri/src/orders.rs::list_parties`：`ptype.filter(|t| !t.is_empty() && *t != "all")`
     ——兜底值不再进 SQL，与 `outbound.rs` 状态筛选口径一致。
  3. `src-tauri/tests/orders_contract.rs` 加 `list_parties_treats_all_as_no_type_filter`。
- 验证：`npx tsc --noEmit --incremental false -p tsconfig.json` 通过；
  `cargo test --test orders_contract list_parties` 2 passed。

**通则（下次别再踩）**：界面筛选的兜底值 `"all"` 只在前端层有意义，跨过 invoke 到 Rust 之前
必须转成 `undefined`/`None`；Rust 侧凡是 `Option<&str>` 的枚举筛选，收到 `"all"`/`""` 一律当不限。

## 改：底栏键盘图标可点了（开「快捷键一览」）

用户反馈磅房工作台右下角键盘图标点了没反应。定位在 `components/business/DeviceStatusBar.tsx`
的 `DeviceStatusStrip`：那颗 `KeyboardIcon` 原本只是 `TooltipTrigger render={<span/>}` 的**纯悬停提示**，
没有 onClick；旁边的「磅/卡/像/印」Chip 是 `<Link to="/devices">` 能点，所以容易被当成按钮。
触屏机上没有 hover → 这颗图标等于死的。

- 新建 `components/business/ShortcutHelpDialog.tsx`：把 `SHORTCUTS` 键位表和 `<Dialog>` 从
  `AppTopbar.tsx` **整体搬出来**，不抄第二份（顶栏以后加键位，弹窗与底栏入口自动同步）。
  顶栏改用 `<ShortcutHelpDialog open onOpenChange>`，F1 的 `useHotkey` 仍在顶栏。
- 底栏图标换成 `Button variant="ghost" size="icon-xs" onClick={() => setHelpOpen(true)}`
  （沿用 `WorkstationPage.tsx:772` 已有的 `TooltipTrigger render={<Button onClick/>}` 写法）；
  Tooltip 受控 `open={hintOpen && !helpOpen}`，免得弹窗开着提示还挂着；提示末行加「点击查看全部（F1）」。
- `DeviceStatusStrip` 有两份实例（AppShell 底栏 + 工作台专注态覆盖层补挂的），`helpOpen` 各是局部 state，
  只有被点的那条开弹窗。

验证：`npx tsc --noEmit --incremental false -p tsconfig.json` exit=0；
`npx vite build --outDir dist-verify --emptyOutDir` built in 4.93s（仅既有 chunk / tauri 动态导入告警）。
