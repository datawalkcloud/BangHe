# 粮站收粮管理系统 · 设计文档

面向乡镇粮站/个体收粮点的**单机桌面版**收粮管理系统设计基线。技术底座复用本仓库 `banghe` 工程（Tauri 2 + React 19 + Vite + shadcn），数据落地本地 SQLite，全部功能离线可用。

当前阶段：**设计基线已定稿（01–07），业务代码按模块从 mock 逐块迁本地真库中**（看板/工作台录单/基础档案已走原生通道，结算中心、作废红冲、设备与参数仍为 mock）。

## 一分钟看懂方案

- **主流程**：建档登记 → 扦样化验 → 一次称重 → 二次称重 → 核算结算 → 台账归档；支持先毛后皮与先皮后毛两种流向
- **最小作业单位**：磅单（一个车次一张单），一个售粮人多车次可合并为一张结算单
- **首版范围**：核心收粮闭环 + 四类外设对接（另有磅房声音链路：人工话筒喊话 + 系统语音播报，P1，见 07）；**不做**库存仓储、财务深化、多站点、监管平台上报
- **明确暂缓**：水分/杂质自动增扣量与等级加减价规则引擎 —— 以 `PricingEngine` trait 承载，首版注入 `ManualPricing`（人工录扣重与单价），但指标值逐项结构化落库，未来上引擎可回填验证
- **不可动摇的三条硬约束**：单据永不物理删除（只能作废/红冲且留授权与原因）；金额与重量全链路禁浮点（0.1 kg 与分 定点整数）；无硬件时可用 Mock + 手录跑完全流程

## 术语表

| 术语 | 含义 |
| --- | --- |
| 粮站 / 收粮点 | 收购站点，本系统一个站点一套部署与一个本地库 |
| 磅点 | 一台地磅及其工位；首版按单磅点设计，数据模型支持多磅点 |
| 毛重 | 车辆 + 装载粮食的总重（上磅一次称重） |
| 皮重 | 空车（含车上固定物）自重（二次称重） |
| 净重 | 毛重与皮重之差，`净重 = \|毛重 − 皮重\|` |
| 分度值 | 衡器的最小读数刻度，60/80 t 汽车衡通常为 10 kg 或 20 kg |
| 包装扣重（袋重） | 编织袋、筐等包装物重量，与质量扣量分列不混项 |
| 扣量 / 增扣量 | 因水分、杂质、不完善粒等指标偏离基准而扣减（或增加）的结算重量 |
| 扣水 / 扣杂 | 水分、杂质超标对应的扣重项 |
| 结算重量 | 净重扣除包装扣重与各项质量扣重后的实际计价重量 |
| 定等指标 | 决定粮食等级的指标（小麦/玉米容重、稻谷出米率与整精米率等） |
| 增扣量指标 | 不参与定等、只用于增减价的指标（水分、杂质、不完善粒等） |
| 容重 | 单位体积粮食质量，g/L，小麦与玉米的定等依据 |
| 不完善粒 | 虫蚀、破损、霉变、未成熟等瑕疵粒的百分比 |
| 黄粒米 / 霉变粒 | 食品安全指标，超限常作拒收红线 |
| 扦样 | 按规范从批次中抽取样品的动作 |
| 检化验 / 快检 | 化验室检测；近红外快速检测仪初检 |
| 磅单 | 记录一次车次称重的单据，业务主单据 |
| 码单 | 结算用的重量与金额明细单（行业常称"收购码单"，一式多份、需售粮人签字） |
| 内部流转单 | 多岗流转场景下的库内传递凭证（IC 卡模式，P1） |
| 红冲 | 已结算单据出错时，开具一张数量与金额均为负的关联单抵消，再开正确单 |
| 作废 | 未到结算状态的单据失效，保留记录与原因，需授权 |
| 挂账 | 已完成结算但粮款未付清的应付款项（整单未付，或部分付款后剩下的余额）；还没结算的磅单不算挂账，那叫待结算 |
| 交粮人 / 售粮人 | 来粮主体；分农户、种植大户、粮食经纪人、合作社、企业五类 |
| 代售清单 | 经纪人替多个实际种粮人交粮时的明细，监管核查重点 |
| 迎检 | 应对粮食行政管理部门与储备粮监管的抽查，需可追溯台账与影像 |
| 日结 | 按自然日或班次封账，输出交接与汇总报表 |
| 最低收购价 | 政策托市价格，涉及专门计价与上报口径（本系统首版不涉及） |
| 承储 / 代储 | 替储备库保管粮食的业务形态，涉及轮换与粮情（P2 之后） |
| 喊话 / PTT | Push-To-Talk，按住说话：磅员对着话筒实时讲话，经电脑直通功放播出（07 §4） |
| 音柱 / 功放 | 磅区外的定向扬声器与其定压放大器；本机声卡只送到功放，音量最终由功放面板决定 |
| 喊话链路（`kind='pa'`） | 一条链路 = 一个话筒端点 + 一个喇叭端点，在 `device_config` 里只占一行（07 §6.1） |
| 通道仲裁 | 人工喊话与系统播报共用一路输出，同一时刻只允许一路出声的互斥规则（07 §3） |
| 片段拼接 | 播报由预录的短音频片段（数字、单位、词组）串接而成，运行期不做语音合成（07 §5.3） |
| MIC 优先 | 功放自带的硬件功能：话筒有信号时自动压低线路输入，是接法 B 能不出双声的前提（07 §2.1） |
