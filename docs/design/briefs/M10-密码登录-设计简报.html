M10 口令登录 · 设计简报

BangHe 收粮计量结算系统  ·  2026-09-11  ·  状态：待拍板（确认后并入 docs/design/03 §9.4 与 05 §3，本文即弃）

一句话主张：口令校验与会话留在 Rust 侧，前端只是这份会话的投影。署名（actor_id）由 Rust 会话决定，不再由前端传参——否则换上的仍然是"可以按 F12 改的身份"，口令只是装饰。

依据：02 §11 要求"用户名口令（argon2 哈希）、连续失败锁定、支持在岗切换而不退出程序、未登录不可进入任何业务页"；02 §11 RBAC 行已明确"前端隐藏 + 后端命令双重校验"；05 行 181 要求破坏性操作"需授权的还要输入站长口令"。库表已备（user_account 有 password_hash/must_change_pwd/failed_count/locked_until/last_login_at，audit_log 有 session_id 与 result 的 denied），本期不需要任何迁移。

1范围

做

  • 真实 auth_login / auth_logout / auth_change_password（Rust，argon2id 校验，读写 user_account）
  • 连续失败锁定（5 次 → 15 分钟），登录成功与拒绝都写 audit_log
  • 首启设置口令（库里是占位符 !set_on_first_run 时开放，无默认口令）；must_change_pwd=1 时强制改密后才进业务页
  • 路由守卫：未登录不进业务页（/login 现在还是 Placeholder）
  • 会话落在 Rust 内存（AppState），前端 useSession 改为它的投影；OperatorProfile DTO 永不含 password_hash
  • 三处身份入口收敛为同一个 <OperatorSwitch/>；文案分叉修掉
  • 四处授权（作废 / 红冲 / 补打 / 皮重越权）复用同一条"输入站长口令"原语

不做（下一轮）

  • 空闲自动锁屏（要新增 app_setting 键，牵动 03 §9 文档与 seed 契约测试，且 0002 已发布不可改 → 必须走 0003 迁移）。本期只做"手动锁屏 / 换人必输口令"
  • PII 字段级 AES-GCM、备份恢复向导、日结交班（同属 M10 其它行）
  • 口令策略硬化（复杂度、有效期、历史不可复用）与 LDAP/域账号

4需要你拍板的 6 件事

D1actor_id 由谁提供推荐 b

(a) 沿用现状：前端传 operator_id，口令只管界面门。 (b) 写命令不收 operator_id，由 Rust 会话注入。 影响：02 §11 RBAC 的"后端双重校验"、以及审计能不能归人。现在只有 5 条已注册命令，(b) 的成本≈0；等 24 表业务命令铺开后再改，就要动所有签名。

D2会话存哪儿、活多久推荐 a

(a) 只存 Rust 内存，重启程序必须重登，换人必输口令。 (b) DPAPI 加密续期 token，重启免密回到上次署名。 影响：磅房机常重启/断电，(a) 每天多输几次口令；(b) 少一次输入，但"署名=物理在场的人"这条就不成立了，而单据是要给农户和审计看的。

D3初始口令怎么来推荐 a

(a) 保持占位符 !set_on_first_run，没有默认口令：首启检测到占位符 → 只开放"设置口令"，不设权限、不设业务页，设成功才建会话；仅在所有账号仍是占位符时可达。 (b) 种子写死一个初始口令（如 banghe@2026）。 影响：(b) 会让同行拿到安装包就能登进去（你多次说过这台机器上的东西会被复用），而且 schema_contract.rs:878 的断言会直接红。 (a) 的残余风险是"能物理操作这台机器的人可抢设口令"，靠首启在安装/部署现场完成来兜。

D4左下角那块还要不要推荐 保留，但降级为换人入口

02 M10 白纸黑字要求"支持在岗切换而不退出程序"，所以下拉不删；删的是"点一下就换人"——换人改为弹出口令框，输入目标账号口令后切会话。同账号的锁屏回来同样要口令。 替代：不做下拉、只在 /login 重登。少一个入口，但磅员交接要重启，违反 M10 那句验收。

D5浏览器（非 Tauri）里演示怎么办推荐 b

守卫一上，纯浏览器打开的演示（现在全站 mock、可发给客户看的那份）会被挡在登录页。 (a) 浏览器直接不给进，只演示打包版。 (b) 识别到无 Tauri 通道就显式进「演示模式」：不做口令校验，但页面顶部常驻一条"浏览器演示 · 口令未校验"的横幅，账号也只从 mock 名单取。 与 native.ts 的既有纪律一致：可以降级，但不能把降级伪装成真在线。

D6口令策略与锁定阈值推荐 6 位 / 5 次 / 15 分

最短 6 位、不强制大小写符号（磅房键盘、全键盘流程、操作员文化）、不设有效期、不做历史复用检查；连错 5 次锁 15 分钟，锁定与失败都进 audit_log（result='denied'）。用户不存在也跑一次 argon2 校验拉平时序，错误文案统一"用户名或口令不正确"，防账号枚举。

5验收口径（写代码前对着它，不另发明）

  • 未登录刷新任意 URL（含 #/orders、#/devices）都落在登录页——对齐 02 M10"未登录不可进入任何业务页"
  • 错口令 5 次后第 6 次给出"已锁定，剩余 N 分钟"，界面不区分"用户不存在/口令错"
  • must_change_pwd=1 的账号登录后只能进改密屏，改完才拿到会话
  • 换人后旧会话立即失效，之后任一写命令用旧 session_id 调用返回拒绝并留 denied 审计
  • 任何 auth_* 返回值与序列化文本中检索不到 argon2 / password_hash（自动化断言，不靠人眼）
  • 05 §10-2、§10-7 两条：全程键盘完成登录到制单；作废 / 红冲 / 补打 / 皮重越权四处授权均生效并留痕
  • 全站检索 operator?.id ?? 0 与 operator! 均为 0 命中
  • cargo test（含新增 auth_contract）全绿，且 schema_contract 13 条不需重 bless

6风险与代价

风险处置
argon2 栈不在 Cargo.lock，需联网拉一次开发机联网 cargo fetch 后提交 Cargo.lock；磅房机只跑安装包，不现场编译，故与 WebView2 offlineInstaller 那条不冲突
argon2 的 50–100 ms 校验阻塞命令队列必须 spawn_blocking；参数按 OWASP（m=19456KiB, t=2, p=1），不做可配置
单 Connection + Mutex：登录校验期间业务读被串行化本期业务命令还没真库化，无实际影响；真库化时按 db/mod.rs:55 约定继续 spawn_blocking，口令路径不持锁做哈希（先取 hash、释放锁、再算）
守卫与"首启无口令"叠加后可能出现启动即卡死在登录页登录页显式给出"本机首次使用 → 设置站长口令"入口，绝不做成失败即静默（你反对启动即失败，宁可显式提示）
mock 与真库并存的过渡态：登录真、业务仍 mock，前端仍传 operator_id本轮把 10 处 ?? 0 与 4 处 operator! 收成 useActorId()，使 mock 也遵守"必须有署名"这条不变式；D1 选 (b) 后，真业务命令上线即沿用会话注入
