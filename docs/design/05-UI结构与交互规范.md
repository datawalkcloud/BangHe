# 05 UI 结构与交互规范

面向实现的前端信息架构与交互约定。视觉体系沿用工程现有 shadcn 配置（`components.json`：style `base-maia`、baseColor `neutral`、cssVariables、`--radius: 0` 直角风格），本文只补充业务侧规范与必须处理的本地化问题。

---

## 1 设计前提（磅房的物理环境）

| 环境事实 | 设计推论 |
| --- | --- |
| 磅房空间狭小，窗口对着磅区，操作者一手扶门一手操作 | 主流程全部可键盘完成；鼠标仅作辅助；按钮点击区 ≥ 36 px |
| 强光、粉尘、可能有雨反光，常远距离给农户展示重量 | 重量显示用超大字号（≥ 96 px）+ 高对比；不用浅色底 |
| 旺季连续作业 10+ 小时，单车次目标 ≤ 3 分钟 | 禁止把关键操作藏进二级弹窗或多步向导；默认值要"猜得准"（上次的品种/仓房/车号） |
| 操作者年龄偏大、电脑熟练度低 | 不使用悬停作为唯一提示；术语用行业话（毛重/皮重/扣杂/码单）而非"实体/记录" |
| 常有纠纷，需要当场给农户看数据 | 每屏可一键"对外大屏"（另起一扇独立窗口挂外屏，放大重量与金额，隐藏操作按钮） |
| 显示器多为 1080p，个别老机 1366×768 | 断点 ≥ 1280 为主设计宽度，1366×768 不得出现横向滚动 |

## 2 应用骨架

```mermaid
flowchart TD
    A["AppShell"] --> B["AppTopbar（顶部工具条，36 px）<br/>折叠侧栏 · 新建过磅单 · 全局检索 · 对外大屏 · 显示模式 · 帮助（快捷键一览 / 审计 / 版本）"]
    A --> C["Sidebar（左侧可折叠，56/240 px）<br/>看板 · 磅房工作台 · 单据中心 · 农户 · 化验 ·<br/>结算 · 基础档案 · 台账报表 · 设备中心 · 系统"]
    A --> D["DeviceStatusBar（底部常驻）<br/>磅：COM3 在线、12,345.6 kg、稳 · 卡：在线 · 刚读 方**梅 ·<br/>像：192.168.1.64 在线 · 印：HP M403d 就绪 · 本机时间 · Mock 关"]
    A --> E["Outlet 页面区"]
```

- 顶栏不再有桌面风格菜单条：原先六组菜单里的跳转项侧栏与页内 tab 已全覆盖，全局动作收进 `AppTopbar`，Mock 总开关落在底栏——**没有功能被删掉**；打印也不再有"通道"可配，工作台固定无预览直打（出口随码单纸型自动分流，失败才弹预览框兜底）
- 底栏状态条常驻且不可隐藏——设备故障是现场最高频问题，必须任何页面都能一眼看到。工作台的「全屏专注」（`F11`）是一层盖住整个视口的覆盖层，它盖掉的是顶栏与侧栏，**底栏这一条必须在专注态照样显示**：专注层底部另挂一份纯展示的状态条，读卡器台账闸门与真机探测仍只有 AppShell 那一份在跑（两个实例同时在场上会抢读卡器）
- 底栏右侧显示本机系统时间（`MM-DD 周X HH:MM:SS`，悬停看完整年月日）：磅房操作员手上是票据、眼睛在车上，抬头对一眼时间比切任何页面都快，秒级对齐整秒边界刷新
- 状态文字同时用图形符号（实心圆/空心圆/三角），不依赖颜色区分（色弱与黑白打印机场景）
- 侧栏支持 `Ctrl+B` 折叠；工作台上建议折叠以腾出横向空间
- 打印窗、对外大屏窗为独立 Tauri 窗口（`label: print` / `label: display`），不参与主路由

## 4 磅房工作台（核心界面）

### 4.0 作业模型（登记弹窗 + 刷卡推进）

工作台不再让"身份与制单"常驻占视线。改后的主链路（详见 06 篇）：

- **登记＝弹窗**。来新人点顶栏「制单」（或 `F7`）弹出"身份与制单"框：框内读身份证认人 / 搜档案 / 手录证号建档 → 选车牌（**品种与去向都是选填**：`variety_id` 自迁移 0017 起可空，品种留到结算框或化验区就地定，见 02 §F1.1）→ **点「取号并制单」再弹一个"请将流转卡贴在读卡器感应区"的寻卡框**，读到一张空闲在册卡才取号，卡与单同一笔事务绑死（06 §4.0）→ 关框。弹窗打开期间 **IC 常听挂起、只解身份证**（一台读卡器一次只认一种介质，06 §1.2），绑卡那一步才切回 IC 通道。读不到卡这张单就制不成；站点不刷卡的退路是把 `card_required_on_create` 关掉（06 §6.4）。
  - **卡先到、人后到＝零按键**。无论卡是后台常听刷到的还是寻卡框贴到的，**只要卡已就位而售粮人还没定，`① 身份与制单` 格子里就自动起一轮 15 秒身份证监听**（`IdCardWatchHint`）：读到证卡 → 认人 → 自动连同 `card_no` 取号制单，全程不再要人点第二下（02 §F1.1 验收已改成"0 次按键"）。监听**不做成弹框**——格子最小只有两格高，弹框会把人从"看车上看读数"里拽走；一行脉冲动画 + 剩余秒数 + 「取消」就够（`aria-live="polite"`，播报沿用 `请将身份证平放在读卡器感应区`）。按「取消」或 15 秒听不到 → 这一格退回原样，`panelHolding` 落下 → IC 后台常听自己回来，等下一张卡（同一次压卡反复刷**不重复取号**：`cardNo + partyId` 认一次）。
  - **读卡读到没建过档的证号＝静默自动建档**，不弹任何框：姓名 / 证号 / 住址 / 人像全部读卡带入，电话留空（它不挡制单，事后再去「农户与单位」补），建好直接选为本单售粮人并连同卡号自动制单（02 §F1.1）。证号是一人一档的财务主键，这里**仍然由服务端 `party_save` 把关**，一人一档的闸门一条不放松。
  - **唯一还问人的情形＝同名且证号为空的旧档**：读进来的证号没建档，档案里却躺着同名、`id_card_no` 为空、状态启用的旧档 → 弹「是否是同一人」（`SamePartyDialog`），候选一行一条，「是本人 · 补录身份证」给旧档补上证号（历史磅单、挂账余额、参考皮重全部沿用），「都不是 · 新建档案」另起一张。认错人等于把两个农户的挂账合成一个余额，这一问省不掉；除此之外制单路上不再有任何二次输入。
  - **自动建档失败才回落到「无档案 · 快捷登记」框**（该岗位无建档权限、库锁）：姓名 / 证号 / 住址读卡带入，只补一个电话（可不填），保存后同样直接选为本单售粮人。框内同时给「搜档案」退路——卡面是熟客、但档案里证号录错过时，搜出来改原档案比在这里再建一张更稳。
  - **建档口径与档案页同一条**：读卡带入即记「已核验」，手工录入为「未核验」；快捷框只收自然人三类（农户 / 种粮大户 / 经纪人），合作社与企业拿的是统一社会信用代码、校验规则不同，走档案页完整表单；开户行、挂账额度、参考皮重同理留给档案页补全。
  - **读卡器不可用时点「新档案」**打开同一张表单手工录入（证号手录即未核验）——外设总开关关掉后的提示语与 05 §10-1「无外设也能完成闭环」都靠这个按钮兑现。
- **默认态＝IC 后台常听**。一关框就恢复 `reader.ic.watch`。制单当场已经把卡绑上（06 §4.0），所以监听此刻的主职是**推进**：此后同一张卡**每刷一次把这张单往前推一步**——①刷捕毛重、②刷捕皮重并**静默出码单**（算好净重直接送打，不弹预览）、③刷**等价于扫这张单的码**——打开「扫码结算」窗口并带上这张单，在那里落价、收款、打凭证，成功后回收卡（06 §2.2）。只有把 `card_required_on_create` 关掉的站点，监听才回到"读到一张空闲卡放上机器 → 按 06 §4.1 把卡**发给**最近无卡的在途单"。
- **刷到在途卡＝先把工作台切到那张单**。定位排在仪表闸门之前：仪表离线、读数未稳、连击落在去抖窗口内，面板照样从上一张单切到这张卡绑的单（`①` 与 `③④` 说的都是它），拦的只是"这一刷写不写库"——操作员刷谁的卡却看着别人的单核对读数，比多刷一次危险（06 §4.2）。
- **面板降级为应急手点**。`③ 称重区` 的捕获按钮保留，作为"无外设也能完成闭环"（§10-1）与读卡器故障时的手点兜底，文案标"（应急手点，正常刷 IC 卡）"。出票/补打不再是常驻的 `⑤` 面板，其「凭票打印」按钮并入"第三刷结算弹窗"（另有顶部 F9 按钮同路）。化验 `④` 仍是旁路可选步，不在刷卡链里。**结算没有"面板上的手点"这条路**：卡刷到第三下等价于扫这张单的码——打开「扫码结算」窗口并带上这张单，落价与收款仍在那一屏完成（02 §F1.4）。

> `① 身份与制单`按最初的版本**回到左栏常驻格子**（`IdentityPanel` 那份表单 + 有单后的只读摘要一起回来）。"制单"弹窗那条路没撤：`F7` / 后台刷到没单可发的空闲卡仍弹同一份 `IdentityPanel`，**弹窗开着时这一格让位**（读卡回读走跨页面共享的设备缓存，两个实例同场会把同一张卡认领两次——两条 toast、两声播报、两次补照片），关框即回到草稿态。
> `⑤ 凭票与打印`仍是撤除状态：出票/补打入口在"第三刷结算弹窗"（`TicketPrintSection`），撤出来的右栏不另塞新面板，谁占哪几格由本人「自定义布局」定（§4.1）。

| ③ 称重区 | 主触发＝刷绑定卡：第一刷捕毛重、第二刷捕皮重（各取此刻稳定读数，未稳则这一刷作废并提示）；面板"捕获"按钮降为**应急手点**。读数不稳定时数字为细体 + "不稳定"文字；稳定后加粗；捕获成功播放轻提示音并短暂高亮 |

### 4.1 自定义布局（千人千面）

上面的三栏是**默认排布**，不是死排布。磅员可把界面改成自己的：顶栏「自定义布局」进入编辑态，拖面板顶部的把手换位、拖右下角改大小、点 `×` 收起，顶栏「面板」再放回来，「恢复默认」一键退回三栏。

| 项 | 规则 |
| --- | --- |
| 归属 | **排布跟人走，不跟机器走**。存 §9.25 `user_preference`（按 `user_id` + 键 `workstation.layout`），磅房机轮班共用也互不覆盖；换台机器登录还是他那套 |
| 编辑态 | 日常界面里格子是死的——一手油一手票据，不能有"手一抖布局就变了"的入口。只有编辑态给把手、给缩放角、给 `×` |
| 网格 | 12 列 × 24 行固定预算，行高由工作区实际高度反算，所以同一份布局在 1080p 与 2K 上是同一张脸，只是每块各自长高一点；1280 px 以下不采信格子几何，按 `y`→`x` 的阅读顺序退回单列堆叠——此时**不给把手**（拖不动的东西不摆出可拖的样子），收起走顶栏「面板」 |
| 每块下限 | 称重区 3×8（要容得下读数）、结算区 2×10（要容得下算价表）等，见 `layout.ts` 注册表；缩到下限即停 |
| 收起 | 是"收起"不是"删除"：那一格连同位置一起留着，再放回来还在老地方；最后一块不许收起 |
| 脏值 | 读回来的 JSON 一律先规整：键不认识就丢、越界夹回来、档案里没有的面板补回默认位（标了「后加面板」的顺带收起），可见项互相压字则整份退回默认——**宁可退回默认，也不能让工作台开不起来** |
| 后加面板 | 新版本给工作台加一块时，`PanelSpec` 带 `defaultHidden`：**老用户存好的排布里它按「收起」补进来**，只登记显隐标记、不动他任何一块格子，顶栏「面板」里勾一下即出。不做这层的话，新面板按默认位补成可见，而老用户的格子通常已经占满 12×24 → 判压字的闸门整份退回默认，升级等于把他排好的界面悄悄重排一遍。没存过排布的账号走默认排布，新面板一进来就在位。**老面板回归**（比如「身份与制单」请回格子里）同理，别以为只有新增才要防重排 |
| 保存 | 停手 400 ms 后落库（拖动中每帧都报新格子，不能每帧写一次），退出编辑态与离开页面时补写；失败上屏提示，不假装"已经保存好了" |
| 专注模式 | `F11` 沿用同一份布局，但强制退出编辑态。让位的是页头与底部「在途单」条，**底部设备状态条照样在场**（覆盖层底部补挂一份，见 §2） |

代价说清楚：原来是三栏各自滚动、整页不出页面级滚动条；自由格子做不到对这个恒成立，改为每块内部滚动、整屏超出时工作区出一条滚动条。

## 6 交互与展示规范

### 6.1 数值展示

| 类型 | 格式 | 示例 |
| --- | --- | --- |
| 重量（明细） | 千分位 + 1 位小数 + 单位 | `12,345.6 kg` |
| 重量（吨，汇总） | 3 位小数 | `12.346 t` |
| 金额 | 千分位 + 2 位小数 + 前缀 | `¥4,287.60` |
| 金额（大写） | 码单必印 | `人民币肆仟贰佰捌拾柒元陆角整` |
| 单价 | 元/公斤，2 位小数、最多 3 位 | `2.28 元/公斤`（录入框单位后缀同为元/公斤） |
| 化验指标 | 2 位小数 + % 或单位 | `14.80 %`、`762 g/L` |
| 时间 | `MM-DD HH:mm`（列表）/`YYYY-MM-DD HH:mm:ss`（详情） | |

所有数值一律 `font-variant-numeric: tabular-nums`，右对齐；单位与数字之间不空格（行业习惯）；负值（红冲）用 `-` 前缀 + 文字"红冲"，**不用颜色单独表达**。

### 6.2 状态色板与文字

| 语义 | 色 | 同时显示的文字 |
| --- | --- | --- |
| 正常/已付清 | 绿 `oklch(0.62 0.16 150)` | 已付清 |
| 进行中/待处理 | 蓝 `oklch(0.58 0.14 250)` | 待结算、待皮重 |
| 警告（停留超时、皮重接近容差、手录） | 琥珀 `oklch(0.72 0.15 75)` | 超 42 分钟、手录 |
| 危险（拒收、超差、作废、离线、未付超期） | 红 `--destructive` | 已作废、离线 |
| 中性（归档、停用） | `--muted-foreground` | 已归档 |

单据状态除色彩徽章外**必须有中文状态文字**（打印黑白、色弱、远程截图沟通都需要）。

### 6.3 表格规范

- 统一 `DataTable`：列显隐与顺序偏好持久化到 `app_setting`（按用户 + 页面 key）
- 默认页大小 50，可选 50/100/200；翻页保留筛选条件（URL 查询参数化，便于贴给同事与审计引用）
- 合计行固定在表尾，来自与列表同一条 SQL 的窗口函数
- 行本身不响应单击：详情一律从表格末列统一的「操作」列进入（`quickDetail.tsx` 的 `detailColumn` 生成，两套 `DataTable` 共用同一份列定义），在当前页右侧弹出详情抽屉（`QuickDetailSheet`，不离开列表）；抽屉里渲染的就是详情整页的完整正文（`OrderDetailBody` / `PartyDetailBody` / `QcDetailBody` / `SettlementDetailBody` 与整页共用一份），全部明细表与付款登记、调整定级、入仓去向、作废等写操作都在其中完成，不再留「完整详情」二次跳转入口
- 「操作」列只挂在**一行确实对应一张单据/档案**的表上（磅单中心、档案、化验台账、结算台账，以及报表明细、在途单、近期交售、结算明细等同口径的表）；纯汇总表、审计日志、称重轨迹、指标明细等没有可打开的详情，就不挂空列
- 一行只留一个自身详情入口：原先由单号、姓名等字段兼任的跳转链接在挂上「操作」列后改回纯文本；内联 `QuickDetailLink` 仅用于指向**另一张**单据的跨单据引用（如质检单列表里的磅单号、付款流水里的关联单据）
- 抽屉宽度 `min(95vw, 1500px)`，按正文最宽的磅单详情（并排两卡 + 称重轨迹 11 列）定；跨单据引用在抽屉内就地切换目标，点去功能页（如扫码结算）的链接先收起抽屉
- `Ctrl+点击` 新窗口打开详情整页（对账时并排看两张单是真实需求）；详情整页路由保留，深链与多窗口照常可用
- 空状态必须给下一步动作按钮（如"今天还没有磅单 → 去工作台开单"），不留纯文案空页

### 6.4 表单与校验

- `react-hook-form` + `zod`，`lib/schema/` 与后端 DTO 字段一一对应；服务端仍必须二次校验
- 错误显示在字段下方，不用 toast 承载字段级错误；toast 仅用于"保存成功/失败 + 可重试"
- 数值字段用文本框 + 掩码，不用 `type=number`（其滚轮误改与小数点/locale 行为在磅房是严重隐患）
- 占位符用独立令牌 `--input-placeholder`（由 `--foreground` 按 32% 透明度混合派生，浅深色共用），**不复用 `--muted-foreground`**——后者同时是字段标签、说明文字、表格次要列的颜色，和正文只差 0.41 明度，磅房字号（`text-xs/sm`）下"空框"和"已填"看不出区别。`src/App.css` 里刻意写成未分层的 `input::placeholder` / `textarea::placeholder` 全局规则（压过分层后的任何工具类），新复制的组件或裸 `<input>` 都拉不回去；日期选择器这类用按钮当输入框的，未选时同样挂 `text-input-placeholder`。另一半根因：preflight 给 `input/textarea/select` 写了 `color: inherit`，而字段容器常是 `<Label class="text-muted-foreground">` 把控件整个包住，录入内容会跟着标签变灰（深色下实测正文 `#a1a1a1` vs 占位符 `#606060`），占位符调多浅都没用；所以 `App.css` 同处还把 `input` / `textarea` / `native-select` 的 `color` 钉成 `--foreground`，祖先写什么文字色都影响不到录入内容
- 保存失败后**表单内容不得丢失**；离开有未保存内容的页面需确认
- 破坏性操作（作废/红冲/撤销结算/恢复备份）统一 `AlertDialog`，要求填原因，需授权的还要输入站长密码，并在确认框中列出后果（"该单已打印 3 联，作废后需重打"）

### 6.5 反馈与异常

| 场景 | 呈现 |
| --- | --- |
| 设备离线 | 底栏常显 + 相关按钮禁用并说明；不弹模态阻断作业 |
| 称重手录 | 捕获按钮旁显式"改为手录"入口，录完单据标记手录并在列表可筛 |

| 抓拍失败 | 单据上"无抓拍"角标，不弹窗 |

| 严重错误（DB/迁移失败） | 全屏错误页含"打开日志目录""导出诊断包""从备份恢复"三个动作 |
| 读卡弹窗弹出 / 闸门拦下 / 一步落成 | 本机扬声器念一句人话（详见下方「磅房语音提示」） |

**磅房语音提示**（站点参数 `reader_prompt_voice`，默认开）：读卡器装在窗口外、地磅在窗外十几米，操作员的手和眼睛都在车与卡上，而且多为中老年——**屏幕角落那行 toast 根本没人在看**。05 §1 早就写了"关键反馈不能只靠视觉"，这一层就是把它补齐。落地只有两个文件：发声与全部判断在 `lib/voice-prompt.ts`，"读卡弹窗什么时候响"在 `hooks/useVoicePrompt.ts`；业务回话在各决策点直接调 `announce()`。出声分两类：

**一类：读卡弹窗弹出，念"该放卡了"**（与屏上标题同一句：`CardScanDialog`/`IcScanDialog` 直接复用标题常量；`CardBindDialog` 标题里的"（IC 小白卡）"是给操作员辨识用的，语音刻意不带括号）

| 弹窗 | 场景 | 话术 |
| --- | --- | --- |
| `CardScanDialog` | 档案页读卡建档、制单弹窗内读卡（F8） | 请将身份证平放在读卡器感应区 |
| `CardBindDialog` | 点「取号并制单」弹的绑卡框（06 §4.0） | 请将流转卡贴在读卡器感应区 |
| `IcScanDialog` | 卡池页「读卡登记」 | 请将流转卡平放在读卡器感应区 |

**二类：操作回话，念"这一步成没成、下一步干什么"**。判据是**这一刻要不要人改动作**：要改动作的（拦下、失败、该换卡、该下车）必须出声；不需要人反应的不出声。

| 环节 | 时机 | 念什么 |
| --- | --- | --- |
| 读卡认人 | 命中档案 / 没建过档 / 档案已停用 | 读卡成功 / 没有这个人的档案，请补个电话先建个档 / 这个人的档案已经停用，不能制单 |

| 刷 IC 推进（后台常听） | 读数未稳 / 仪表离线 / 读数为零 / 毛重落库 / 皮重落库 / 皮重超容差 / 捕获失败 / 单已结算 / 卡挂的单已不存在 / 外来卡用不了（自动登记失败·未登记且本站关掉了「允许使用未登记的流转卡」·已注销·挂的单不在途）/ 发卡成功·失败（**新卡自动登记成功不出声**，紧接着发卡/制单那一路自己说话） | 读数还没稳定，等车停稳再刷一次 / 仪表离线，这一刷没有记上 / 读数是零，这一刷不记账 / 毛重已捕获，请卸货后再来一次 / 皮重已捕获，可以下磅了 / 皮重偏差超出容差，请核对车上有没有留人 / 捕获失败（两种：单被改过、读数没丢再刷一次）/ 这张单已经结算完了，把卡收回来 / 这张卡的单已经没有了，请重新制单 / 换一张卡（登记不上、没登记过、已注销同话术）/ 卡已经发出，请把卡交给农户 / 这张卡发不出去，请到工作台上手点制单 |

| 结算 | 结算完成（付清 / 部分付款 / 整单挂账，按服务端返回的结算单差额判档）/ 失败 / 该品种等级无生效价 / 带出现价成功 / 按提交被拦 | 结算完成，款已付清 / 结算完成，这一单只付了一部分，剩下的挂账 / 结算完成，这一单全额挂账，凭证留好 / 结算没有成功，填的内容没有丢，可以再结一次 / 这个品种这个等级没有生效价，要手填单价 / 已带出价目表的现价 / 照 `blocked` 原文念。**三档都不念金额与单号** |
| 出票 | 自动出纸失败 | 码单没能自动出纸，请在预览框里手动打一次。**成功不念**：纸从出纸口出来比任何语音都直接，紧跟的一句还会把上一声掐断 |

四条规矩：

- **只播动作与结论，不播编号与数字**：卡号是十六进制串、重量是定点小数、单号带站码，念出来既听不懂又拖长句子；姓名同样不播（本机喇叭也是在磅房里公开响，与 07 H12 同一条合规线）。编号与数值归屏幕和码单。服务端回的原因带条款带单号，一律**换成一句结论**再念，原文照旧留在 toast 里。
- **一次只念一句，同一件事 3 秒不重念**：投递前先掐掉上一句（连着两件事不许叠音）；`announce` 的去重键**照抄那条 toast 已经在用的 `sticky(id)`**——同一件事在屏幕上只占一个框、在喇叭里也只响一次，不另立一套编号。卡压在感应区不动、连点两次按钮都不会变成复读机。
- **关窗只掐弹窗那句，不掐业务回话**：读卡弹窗关闭时把没念完的"请将卡放到……"停掉是对的（卡已经放上去了，再念是抢话）；但绑卡框读到卡是**先播报再关框**，无差别 cancel 会把"卡读到了，正在取号制单"念成半句。分界就是有没有去重键：弹窗提示不带键、业务回话必带。
- **开关只闸声音 + 绝不允许静默失败**：`reader_prompt_voice=false` 后彻底静音，读卡、称重、结算、绑卡闸门一律照旧。闸门同步挂在应用根（`App.tsx`）一处、全应用一份，参数还没读回来时先不出声（免得站长明明关了仍抢跑念一句），读回来确认库里没这个键才按默认的「开」走。这台机没有语音接口、或只装了非中文语音包（英文引擎念中文只会不出声）时降级成两声提示音，并把"为什么不是人声 + 怎么恢复"上一条 toast 说明，**一次会话只说一次**；连提示音都放不出（没接扬声器）也只是一条说明，不阻断任何作业。

**边界**：走 WebView2 平台语音合成（Windows 自带中文语音包，不联网、不引第三方 TTS、不加音频资源包），只服务弹窗与工作台所在这一台机器的近场提示。它与 07 篇「功放 + 音柱 + 预录片段包」的喊话链路是**两条独立通路**——不进车间喇叭、不参与 07 §3 的通道仲裁、不需要 07 §5.3 的片段工装。上面这些回话与 07 §5.1 的播报事件（毛重/皮重/结算）语义重合是**有意的**：将来 PA 链路落地时把这里的句子喂进功放即可，同一句话届时由哪一路出声归 07 定，本层不预先接线。

### 6.6 权限与只读

`viewer`（查询/审计）角色：隐藏所有写操作按钮，导出与打印保留；命令层同样拒绝，返回 `denied` 并写审计（越权尝试必须留痕）。

## 7 视觉与本地化规范

### 7.1 中文字体（工程当前存在的具体问题）

`src/App.css` 中 `--font-sans: 'Inter Variable', sans-serif`，而 Inter 不含 CJK 字形。若不处理，中文会掉到浏览器默认字体，与数字混排时行高与基线不齐。需在 `@theme inline` 中显式补 CJK 回退：

```css
@theme inline {
  --font-sans: 'Inter Variable', 'Microsoft YaHei', 'PingFang SC',
               'Noto Sans SC', sans-serif;
}
```

数字使用 `Inter Variable`（自带 tabular figures，需开启 `font-feature-settings: "tnum"`），中文使用系统雅黑，兼顾观感与离线可用（磅房机不能依赖联网下载字体）。磅单打印模板另需内嵌宋体系以保证套打一致性。

### 7.2 图表与语义色

现有 `--chart-1..5` 为灰阶，用于报表会无法区分配色（品种占比、等级分布）。需在 `:root` 追加业务语义色与彩色图表序列（不改 shadcn 生成的类名），并把 `--radius: 0` 保留（`base-maia` 直角体系，与"票据/表格"气质一致，不额外改圆角）。

要求：图表同时给出数据标签或提供可切换的表格视图（打印后为黑白）。

### 7.3 尺寸与密度

| 项 | 规范 |
| --- | --- |
| 基准字号 | 14 px（`text-sm`），表格 13 px，辅助 12 px，重量展示 96–160 px |
| 控件高度 | 36 px（`h-9`）；工作台主操作按钮 44 px |
| 间距阶 | 4/8/12/16/24/32，禁止散落的奇数值 |
| 页面留白 | 内容区左右 24 px，标题区高 56 px |
| 弹窗宽 | 表单 480 px / 明细 720 px / 导入向导 960 px |
| 侧栏 | 展开 240 px，折叠 56 px |

### 7.4 深色模式与主题配置（已实现）

出厂默认**浅色**：磅房白天强光下深色对比更差。可选深色（夜班、遮阳棚内）与跟随系统；入口有两处——顶栏工具条的显示模式按钮（按钮上就是当前档位名）和 `/system/appearance`。

- 模式由 `next-themes` 管理 `<html>` 上的 `.dark` 类（`src/components/ui/sonner.tsx` 读同一上下文），色板由 `src/lib/theme.ts` 注入 `:root` + `.dark` 两段 CSS 变量覆盖；两者各存一个 localStorage 键（`banghe.theme.mode` / `banghe.theme.palette`），挂载前由 `bootstrapTheme()` 先打上，避免首帧闪白。
- 色板结构照 shadcn 官方主题编辑器：**基础色板**（Neutral / Stone / Zinc / Mauve / Olive / Mist / Taupe）给全套灰阶令牌，**主题色**只覆盖 `primary`、`secondary`、`chart-1..5`、`sidebar-primary` 等少数令牌。数值不手抄，由 `tools/gen-theme-presets.mjs` 从 `shadcn-ui/ui` 的 `apps/v4/registry/themes.ts` 生成 `src/lib/theme-presets.ts`。唯一手写的主题色是 **磅禾绿**（`src/lib/theme.ts` 的 `BRAND_ACCENT_THEME`，也是出厂默认）：色相取自 logo 主色 `#34914f`，但明度压到 `oklch(0.515 0.105 151)`（≈ `#327847`）——`--primary` 在界面里既当按钮底色又当 `text-primary` 前景色，直接用 logo 原色对白底只有 3.79:1，压一档后 5.14:1 过 AA。
- **重置默认主题** = 移除注入的 `<style id="banghe-theme">` 并把模式改回浅色，外观重新完全由 `src/App.css` 决定。生成脚本会逐令牌校验"默认色板（neutral + 磅禾绿）== `App.css` 的 `:root`/`.dark`"，一旦漂移就构建失败——否则重置会变成悄悄换一副样子。品牌令牌从 `src/lib/theme.ts` 读回来比对（不复制第二份），`App.css` 自加的工程令牌（`--component-shadow`、`--sidebar-active-fg` 等）与 `DEVIATIONS` 里写明原因的刻意偏离项不参与比对。
- 三处刻意的边界：① 不提供圆角调节，`--radius` 固定 0（base-maia 直角，§7.2）；② 主题色不改图表配色，`--chart-color-1..5` 是品种/等级的业务语义色（§7.2）；③ 主题是**本机显示偏好**，即时生效、只存本机，不写 `app_setting`、不留审计、不需要站长权限——会影响单据内容的选项一律留在「基础档案 → 站点参数」。
- **打印一律浅色**：单据模板（`components/print/sheets.tsx`）本身就是固定黑白，但列表页与审计页直接 `Ctrl+P` 出纸会带上屏幕配色。因此 `beforeprint` 临时摘掉 `.dark`、`afterprint` 还原（`src/lib/theme.ts` 的 `guardPrintTheme`），等价于用当前色板的 light 值出纸；刻意不在 CSS 里再抄一份浅色令牌，免得形成第二套真相。
- **窗口标题栏跟着深浅走**：上沿那条标题栏是 Windows 自己画的，不归 CSS 管，而 Tauri 自带的 `window.setTheme()` 在 Windows 上只设 WebView2 的 preferred color scheme（`wry` 里就是 `Profile.SetPreferredColorScheme` 一句），实测碰不到标题栏。所以由 `src/lib/titlebar-native.ts` 把「此刻是不是深色」送到 `src-tauri/src/titlebar.rs` 涂 DWM 的 `DWMWA_USE_IMMERSIVE_DARK_MODE`（先按标准值 20 试，失败再试 Win10 1809 之前的 19）。口径四条：① 真相只有一个——**以 `<html>` 上真正生效的 `.dark` 类为准**，用 MutationObserver 盯着，谁改的（设置面板、"跟随系统"被 next-themes 解析、以后的新路径）都自动覆盖，不存在"接了三处漏一处"；② 启动点唯一在 `src/main.tsx`，早于 React 挂载，深色用户不会先看到一条白标题栏，主窗口与对外大屏窗各跑一份 `main.tsx` 同时生效（命令按 invoke 来源注入窗口，涂的正是发起方那条）；③ 打印期间挂起——打印守卫临时摘 `.dark` 是给纸面的，不该让标题栏每打一张纸闪一次浅色，`afterprint` 恢复时按真实类名补涂；④ 失败一律静默（老系统、无桌面合成涂不动，只影响观感，绝不为一个颜色弹错误框）。不做 Win11 才支持的 `DWMWA_CAPTION_COLOR` 精确同色：Win10 上没这属性，装了 Win10 的磅房会看到"另一套东西才生效"，宁可两边一致地只有深/浅两态。它是本机显示偏好的一部分，同样不进 `app_setting`、不留审计、不给开关。

## 8 组件与代码规范

- UI 原子组件一律取自 `@/components/ui`（shadcn 生成，不手改；改动需通过重新 `add` 覆盖或包一层业务组件）
- 业务组件放 `@/components/business`，命名表达领域而非样式：`WeightDisplay`、`OrderStatusBadge`、`IndicatorInput`、`DocTimeline`、`PartyPicker`、`MoneyInput`、`TareToleranceAlert`
- **禁止在页面里出现 `/10`、`*100`、`toFixed(2)`**：换算与格式化只允许来自 `lib/format.ts`
- 所有后端调用只经 `lib/api.ts`（唯一 `invoke` 出口），按模块分组导出，返回类型与 `models/dto.rs` 对齐；组件不出现字符串命令名
- 查询 key 约定：`["orders", filters]`、`["order", orderNo]`、`["parties", query]`、`["report","daily", date]`；写操作成功后显式 `invalidateQueries`，禁止整页 reload
- 设备实时数据只进 `store/device.ts`（zustand），不进 react-query 缓存（高频、非服务端状态）
- 页面文件只负责组合与路由参数，逻辑超 150 行即抽 hook（`useWorkstation`、`useOrderQueries`、`useScaleWeight`）
- 图标统一 `lucide-react`；重量/金额等关键区域不使用 emoji

### 9.1 小票模板编辑器的屏上交互（`components/print/receipt/TemplateEditor.tsx`）

一张票 = **一组有序区块**（字段区 / 表格区 / 署名区 / 文本行 / 码）。左栏那份列表与右栏那张纸必须是同一件事的两个视图，否则站长改完不知道改在哪儿：

- **点左栏任一区块 → 预览里对应的那一格描一圈并滚进视野**。纸面常常比预览框长好几屏，只描边不滚动等于让人自己找。这圈描边不是票面内容：离屏 iframe 打印文档的基础样式与 `@media print` 两处都把它抹掉（见 `printPage.ts`）。
- **字段区里那一列的顺序就是打印顺序**。从前这里显示的是"按字段目录排好"的假顺序，而票面按勾选顺序印——两件事一旦不一致，站长眼里的结论就是"排序和预览不一致"。所以清单按 `fields` 数组原样列出、可上下调，同组字段被别的组隔开时**不合并**（`render.tsx` 的 `kvClusters` 只与紧邻的同组段合并），小票机路径共用同一函数，纸上与预览一起跟着这条规则走。
- **没有内容的区块在预览里留一格虚线占位**，写明"打印时跳过本区块"。让它从票面上凭空消失，"左栏第 3 块"就到票上成了第 2 样；这格占位只给编辑器（业务出纸不传该标记），因为它占版面高度，热敏卷纸"先量后打"会因此多拖一截空白。
- **码区块可切「码制」（仅二维码 / 仅一维条码 / 两者都打）与「尺寸」**，并就地报出这一档在当前纸型上量到的真实毫米数（含"纸放不下、已压到 N 点/模块"）——能不能扫看的是毫米，不是"大/中/小"这种形容词。没动过码制的老模板照旧只出二维码，一维码不会无中生有。

## 10 首版 UI 验收清单

1. 断网、无外设（Mock 关闭）情况下，手工录入可完成一个车次闭环并打出码单
2. 全程键盘完成主流程，不用鼠标也能开单到打印
3. 1366×768 与 1920×1080 均无横向滚动、无文字截断
4. 任一金额/重量在界面、打印件、xlsx 三处逐分逐 kg 一致
5. 所有状态既有颜色也有文字；黑白打印后仍可判读
6. 设备离线时不出现模态弹窗阻塞，底栏可定位到具体设备与原因
7. 作废、红冲、补打三处授权均生效并留痕；皮重偏差超容差不走授权，改为照常入账 + 磅单醒目警示并写审计
8. 台账导出文件用 WPS 与 Excel 打开均无列错位、无数字变科学计数法
9. 语音两类都出声：读卡类弹窗（读卡建档 / 制单读卡 / 制单绑卡 / 流转卡登记）弹出即念"请放卡"；工作台上读数未稳、外来卡用不了、档案停用、重量落库、结算完成、码单没出纸各回一句。同一件事连做两次只念一次，且念的都是动作与结论——不念单号、卡号、姓名、重量。把 `reader_prompt_voice` 关掉或这台机压根没有语音包，读卡、称重、结算闭环照旧完成
